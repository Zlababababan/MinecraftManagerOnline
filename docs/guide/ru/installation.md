# Установка

[English](../installation.md) · [Français](../fr/installation.md) · [Español](../es/installation.md) · [Deutsch](../de/installation.md) · [Português](../pt/installation.md) · **Русский** · [中文](../zh/installation.md)

_Перевод английской версии, которая является эталонной. Интерфейс приложения доступен на английском и французском языках._

Руководство пользователя — установите **панель** (одна машина, та, что остаётся включённой), затем **агент** на каждой машине, где размещены серверы Minecraft (часто это та же самая машина). Всё поставляется в виде самодостаточных архивов: заранее устанавливать Node, Java или Python не нужно.

Платформы с готовыми сборками: **Windows x64**, **Linux x64**, **Linux ARM64** (Raspberry Pi 4/5, ARM-серверы), **macOS Apple Silicon**. Windows ARM64 работает с архивом x64 (эмуляция). Intel macOS не пакетируется.

**Какие дистрибутивы Linux?** Начиная с 1.0.5 панель не содержит скомпилированных модулей, поэтому **подходит любой дистрибутив на основе glibc**: Ubuntu 20.04 и новее, Debian 11 и новее, Fedora, Rocky/Alma/RHEL 9, openSUSE, Raspberry Pi OS, Oracle Linux, Arch… Ничего устанавливать не нужно — ни компилятор, ни пакеты для разработки. Единственное исключение — **Alpine** и другие системы на musl, которые встроенная среда Node не поддерживает: используйте официальный образ Docker (§1.2 — он несёт свою libc), дистрибутив с glibc или запустите панель на собственном Node ≥ 24 (`node app/dist/main.js` из распакованной папки).

## 1. Панель

### 1.1 Загрузка

Откройте [страницу релизов](https://github.com/Zlababababan/MinecraftManagerOnline/releases/latest) и скачайте файл, подходящий вашей машине:

| Ваша машина                                    | Файл для загрузки                         |
| ---------------------------------------------- | ----------------------------------------- |
| Windows (любой современный ПК)                 | `mmo-panel-<version>-win-x64.zip`         |
| Linux на обычном ПК или сервере                | `mmo-panel-<version>-linux-x64.tar.gz`    |
| Linux на ARM (Raspberry Pi, ВМ Oracle/Ampere…) | `mmo-panel-<version>-linux-arm64.tar.gz`  |
| Mac с Apple Silicon (M1–M4)                    | `mmo-panel-<version>-darwin-arm64.tar.gz` |

Не знаете, какой у вас Linux? Выполните `uname -m`: `x86_64` — это x64, `aarch64` — это ARM64.

Архив самодостаточен: он несёт собственную среду Node, панель, веб-интерфейс и установщики агента для всех четырёх платформ. **Заранее ставить ничего не нужно** — ни Node, ни Java, ни компилятор, ни пакеты для разработки.

> Хотите проверить загрузку? Каждый релиз публикует также `panel-<платформа>.json` с ожидаемой суммой SHA-256. Сравните её с выводом `sha256sum <файл>` (Linux/macOS) или `Get-FileHash <файл>` (Windows).

### 1.2 Распаковка и запуск

**Linux, одна команда.** На машине с systemd (Ubuntu, Debian, Fedora, Raspberry Pi OS…) одно копирование-вставка делает всё, что описано в §1.1–§1.4 — загрузка, проверка SHA-256, код в `/opt/mmo-panel`, данные в `/var/lib/mmo-panel`, настройки в `/etc/mmo-panel/panel.env`, усиленный systemd-юнит, — а затем ждёт, пока панель ответит:

```bash
curl -fsSL https://github.com/Zlababababan/MinecraftManagerOnline/releases/latest/download/install-panel.sh | sh
```

Для **обновления запустите ту же команду ещё раз**: база данных сначала копируется, и если новая версия не стартует, возвращается предыдущая. `--uninstall` удаляет установку (`--purge` удаляет и данные), `--help` перечисляет остальные параметры (офлайн-установка `--archive`, `--dir`, `--data-dir`…). Если вы предпочитаете видеть каждый шаг, ручной путь ниже полностью поддерживается — установщик и ручной путь приводят к одному и тому же результату.

**Docker.** Официальный образ (мультиархитектурный x64/ARM64, агенты внутри) — ответ для машины на Alpine/musl или если у вас и так всё в контейнерах. Скачайте только [docker-compose.yml](https://github.com/Zlababababan/MinecraftManagerOnline/blob/main/docker-compose.yml), затем:

```bash
docker compose up -d
```

Панель отвечает на `http://127.0.0.1:3000`. Данные живут в **именованном томе** `mmo-data` — не поддавайтесь искушению сделать bind-монтирование `./data`: созданное root при первом `up`, оно в точности воспроизводит ошибку прав «не удаётся открыть базу данных», ведь контейнер работает от пользователя `node` (uid 1000). Внутри контейнера панель слушает все интерфейсы (осознанное решение образа): реальную доступность определяет строка `ports:` — оставьте `127.0.0.1:3000:3000` и поставьте `tailscale serve` (§3) на хосте либо открывайте порт осознанно. CLI: `docker compose exec panel /app/entrypoint.sh doctor` (аналогично `setup`, `restore`).

**Windows, одна команда.** Та же идея, в PowerShell (повышение прав он запрашивает сам) — код в `C:\Program Files\mmo-panel`, данные в `C:\ProgramData\mmo-panel`, служба Windows с отложенным автозапуском:

```powershell
& ([scriptblock]::Create((irm https://github.com/Zlababababan/MinecraftManagerOnline/releases/latest/download/install-panel.ps1)))
```

Запустите её снова, чтобы обновиться (сначала резервная копия, откат, если новая версия не стартует). Параметры: `-Port`, `-Archive` (офлайн), `-MigrateFrom C:\старый\panel` (копирует данные прежней ручной установки с проверкой `integrity_check`, не трогая оригинал), `-ServiceAccount User` (если резервные копии идут на сетевой диск), `-Uninstall` (`-Purge` удаляет и данные). Ваш выбор запоминается для следующего обновления.

Установщик также добавляет **MinecraftManagerOnline** в меню «Пуск»: маленький значок рядом с часами — левый клик открывает интерфейс, правый предлагает открыть, логи, запуск/остановку/перезапуск, «запускать вместе с Windows» и выход. Значок управляет службой (он никогда не поднимает вторую панель); при установке без службы он сам запускает панель, а выход её останавливает.

**Windows, ручной путь.** Правый клик по `.zip` → **Извлечь все**, в папку, которую вы намерены сохранить, например `C:\mmo\panel` (не «Загрузки» и не рабочий стол). Откройте эту папку и дважды щёлкните **`mmo-panel.cmd`**. Откроется чёрное окно и останется открытым: это и есть работающая панель, а закрытие окна её останавливает — §1.4 превращает это в настоящую службу. Из терминала:

```powershell
C:\mmo\panel\mmo-panel.cmd
```

**Linux.** В терминале, в папке со скачанным файлом:

```bash
tar -xzf mmo-panel-*.tar.gz
cd mmo-panel
./mmo-panel.sh
```

Для пробы этого достаточно. Для машины, которая будет работать постоянно, положите её в постоянное место — и не забудьте про `chown`, ошибку, которая стоит больше всего времени:

```bash
sudo mkdir -p /opt/mmo && sudo tar -xzf mmo-panel-*.tar.gz -C /opt/mmo
sudo chown -R "$USER" /opt/mmo/mmo-panel   # распаковано от root — передайте пользователю, который её запускает (§1.4 передаёт её служебной учётной записи mmo)
/opt/mmo/mmo-panel/mmo-panel.sh
```

**macOS** — те же команды, что и в Linux. При первом запуске macOS может отказаться выполнять скачанный бинарник: «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть».

> Что-то не так? `mmo-panel.cmd doctor` (Windows) или `./mmo-panel.sh doctor` (Linux/macOS) проверяет среду выполнения, папку данных и её владельца, базу данных и порт и подсказывает, что делать — см. §1.6.

Панель слушает `http://127.0.0.1:3000` (никогда все интерфейсы — наружу её выводит слой доступа, §3; `0.0.0.0` отклоняется при запуске). Полезные переменные: `MMO_PORT`, `MMO_HOST` (конкретный адрес), `MMO_DATA_DIR` (по умолчанию `./data` рядом со скриптом — **именно эту папку нужно резервировать**: база SQLite, метрики, сертификаты, релизы). Помимо консоли панель пишет свой журнал в `data/logs/panel-<date>.log` (хранится 14 дней) — туда и смотрят, когда что-то пошло не так уже после закрытия окна.

### 1.3 Первый запуск

Откройте `http://127.0.0.1:3000`. На машине без экрана (сервер, ВМ) есть два пути: сначала настроить удалённый доступ (§3 — установить Tailscale, выполнить команду `tailscale serve`, затем открыть `https://<машина>.<tailnet>.ts.net` с другого устройства) либо воспользоваться SSH-туннелем (`ssh -L 3000:127.0.0.1:3000 пользователь@машина`, затем открыть `http://127.0.0.1:3000` локально). Мастер состоит из двух шагов — **Administrator account** (учётная запись администратора: имя пользователя, пароль, язык), затем **Access** (доступ): **публичный URL панели** (на этом этапе необязателен), **режим доступа** (см. §3) и **папка резервных копий по умолчанию**. Публичный URL можно изменить в любой момент в Settings → General: именно он подставляется в команды установки агентов и в push-уведомления — задайте его, как только удалённый доступ будет готов.

**Совсем без браузера** (облачная ВМ, контейнер, cloud-init) учётная запись администратора создаётся из командной строки — `setup` — это ровно тот же код, что и мастер. На свежей облачной ВМ, доступной по SSH (Oracle, AWS, Hetzner…), вся последовательность выглядит так:

1. **Установка** — установщик одной командой из §1.2 делает всё, включая службу:

   ```bash
   curl -fsSL https://github.com/Zlababababan/MinecraftManagerOnline/releases/latest/download/install-panel.sh | sh
   ```

2. **Создание учётной записи администратора.** Установщик запускает панель от служебной учётной записи `mmo`, данные — в `/var/lib/mmo-panel`; выполните `setup` от того же имени:

   ```bash
   sudo -u mmo MMO_DATA_DIR=/var/lib/mmo-panel /opt/mmo-panel/mmo-panel.sh setup --username admin --random-password
   ```

   Сгенерированный пароль выводится один раз — сразу скопируйте его. Чтобы задать пароль самому, используйте `--password-stdin` (`echo -n 'секрет' | … setup --username admin --password-stdin`) или `--password-file <файл>` — никогда не передавайте его аргументом: командная строка видна всем процессам машины. `--public-url`, `--locale` и `--access-mode` необязательны. Повторно команда выполняться откажется. При ручной установке (§1.2), где данные лежат рядом со скриптом и принадлежат вам, префикс не нужен: `/opt/mmo/mmo-panel/mmo-panel.sh setup --username admin --random-password --public-url panel.example.net`.

3. **Проверка.** `doctor` (§1.6) осматривает всю установку, а журнал панели идёт через journalctl:

   ```bash
   sudo -u mmo MMO_DATA_DIR=/var/lib/mmo-panel /opt/mmo-panel/mmo-panel.sh doctor
   journalctl -u mmo-panel -f
   ```

4. **Открыть интерфейс со своего компьютера** (§3). Либо установите на ВМ Tailscale и опубликуйте панель в своём tailnet:

   ```bash
   tailscale serve --bg --https=443 http://127.0.0.1:3000
   ```

   и откройте `https://<vm>.<tailnet>.ts.net` — либо, чтобы быстро взглянуть, ничего не устанавливая, поднимите SSH-туннель: `ssh -L 3000:127.0.0.1:3000 пользователь@vm`, затем откройте `http://127.0.0.1:3000` у себя.

**С cloud-init** та же последовательность может выполниться при самом первом запуске ВМ, ещё до вашего первого входа. Берите `--password-file` с файлом, положенным через `write_files`, а не `--random-password`, чей единственный вывод потеряется в журналах cloud-init. Файл может лежать внутри `/var/lib/mmo-panel`: установщик передаёт всю эту папку учётной записи `mmo`, так что панель сможет его там прочитать.

```yaml
write_files:
  - path: /var/lib/mmo-panel/admin-password
    permissions: '0600'
    content: |
      выберите-здесь-длинный-пароль
runcmd:
  - curl -fsSL https://github.com/Zlababababan/MinecraftManagerOnline/releases/latest/download/install-panel.sh -o /run/install-panel.sh
  - sh /run/install-panel.sh
  - sudo -u mmo MMO_DATA_DIR=/var/lib/mmo-panel /opt/mmo-panel/mmo-panel.sh setup --username admin --password-file /var/lib/mmo-panel/admin-password
  - rm -f /var/lib/mmo-panel/admin-password /run/install-panel.sh
```

Две вещи, которые стоит знать. Cloud-init выполняется от root и без терминала: ни одна команда не должна ждать нажатия клавиши — `install-panel.sh` никогда этого не делает, это одно из его правил. И сеть не всегда поднята к моменту запуска `runcmd`: если загрузка не удалась, достаточно повторить ту же команду вручную, как только ВМ станет доступна.

### 1.4 Запуск при загрузке системы (служба)

> Установили одной командой (§1.2, Linux или Windows)? Служба уже создана — этот раздел для ручных установок.

**Windows** (shawl входит в архив) — в PowerShell **от имени администратора**:

```powershell
cd C:\mmo\panel
.\shawl.exe add --name mmo-panel --cwd C:\mmo\panel --log-dir C:\mmo\panel\logs --restart -- C:\mmo\panel\runtime\24.19.0\node.exe C:\mmo\panel\app\dist\main.js
sc.exe config mmo-panel start= delayed-auto
Start-Service mmo-panel
```

Служба будет работать от `LocalSystem`; чтобы запускать её от вашей учётной записи (рекомендуется, если резервные копии идут на сетевой диск), используйте `services.msc` → «Вход в систему» или повторите процедуру агента (§2.2). Переменные окружения (`MMO_PORT`…): `shawl add --env MMO_PORT=3000 …`.

> Важно: `mmo-panel.cmd` задаёт `MMO_WEB_DIR` и `MMO_DIST_DIR`; при использовании shawl добавьте их явно: `--env MMO_WEB_DIR=C:\mmo\panel\web --env MMO_DIST_DIR=C:\mmo\panel\dist-agent --env MMO_DATA_DIR=C:\mmo\panel\data`.

**Linux** (systemd) — `/etc/systemd/system/mmo-panel.service`:

```ini
[Unit]
Description=MinecraftManagerOnline panel
After=network-online.target
Wants=network-online.target

[Service]
User=mmo
WorkingDirectory=/opt/mmo/mmo-panel
ExecStart=/opt/mmo/mmo-panel/mmo-panel.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd --system --home-dir /opt/mmo/mmo-panel --shell /usr/sbin/nologin mmo
sudo chown -R mmo /opt/mmo/mmo-panel
sudo systemctl daemon-reload && sudo systemctl enable --now mmo-panel
```

**macOS** (launchd) — `/Library/LaunchDaemons/com.mmo.panel.plist` с `ProgramArguments` = `/opt/mmo/mmo-panel/mmo-panel.sh`, `RunAtLoad` и `KeepAlive` в `true`, затем `sudo launchctl bootstrap system /Library/LaunchDaemons/com.mmo.panel.plist`.

### 1.5 Обновление панели

Панель сама сообщает о выходе обновления: администраторы видят баннер, как только опубликована новая версия (лента релизов GitHub опрашивается не чаще раза в 6 часов — Settings → General выключает проверку, а категория уведомлений «New panel version published» звонит в колокольчик).

Установили одной командой (§1.2, Linux или Windows)? Запустите ту же команду ещё раз — она сделает резервную копию базы, подменит код, перезапустит службу и сама откатится, если новая версия не стартует. Ручные установки: остановите службу, распакуйте новый архив **поверх** (папки `data/` в архиве никогда нет), запустите снова. Миграции базы выполняются при старте. Новый архив содержит агентов той же версии: панель публикует релиз агента автоматически, и если отмечено «Update agents automatically when they connect» (обновлять агентов автоматически при подключении) (Settings → General — по умолчанию не отмечено), каждый агент обновится при следующем подключении, с автоматическим откатом при неудаче. Иначе обновляйте их по одному в карточке Agent на странице каждой машины.

### 1.6 Когда панель не запускается: `doctor`

Прежде чем читать стек вызовов, спросите у панели, что не так. Она проверяет среду выполнения,
загружаемые модули, каталог данных (**настоящая** запись плюс сравнение владельца с текущим
пользователем), базу данных, порт и веб-интерфейс.

```powershell
C:\mmo\panel\mmo-panel.cmd doctor
```

```bash
/opt/mmo/mmo-panel/mmo-panel.sh doctor
```

Каждая строка начинается с `ok`, `warn` или `ERROR`, и каждая ошибка говорит, что делать — включая
точную команду `chown`, когда архив распакован через `sudo`, а панель работает от другого
пользователя. Команда завершается с кодом 1 при первой же неудачной проверке, так что её можно
использовать в скрипте.

### 1.7 Резервное копирование и восстановление панели

Панель раз в сутки копирует сама себя (согласованная копия `VACUUM INTO` её базы) в `data/backups/panel/mmo-<date>.db`, хранится 7 копий; Settings → Panel backups позволяет создать копию вручную. Метрики (`metrics.db`) не копируются: они восстановимы и велики. Сохраняйте также всю папку `data/`, если хотите сохранить сертификаты и архивы агентов.

Для **восстановления**: остановите панель (служба или Ctrl+C), затем:

```powershell
C:\mmo\panel\mmo-panel.cmd restore mmo-2026-08-23T01-00-00.db
```

```bash
/opt/mmo/mmo-panel/mmo-panel.sh restore mmo-2026-08-23T01-00-00.db
```

Для копии, лежащей в `data/backups/panel/`, достаточно имени файла; полный путь тоже принимается. Копия проверяется (`integrity_check`), текущая база сохраняется как `mmo.db.before-restore-<date>`, после чего панель можно запускать: агенты переподключаются со своим прежним секретом, а размещённые на них серверы переусыновляются с теми же идентификаторами (маркер `.mmo-server.json`). Всё созданное после копии (пользователи, привязанные машины, настройки) теряется: машину, привязанную после копии, придётся привязывать заново. Восстановление откажется работать, если `mmo.db-wal` не пуст (панель ещё работает или была убита резко — запустите её, остановите корректно и повторите).

## 2. Агенты

Один агент на каждую машину с серверами. Он подключается к панели **исходящим** соединением (WebSocket): на машинах с агентами не нужно открывать ни одного порта.

### 2.1 Команда в одну строку

В панели: **Machines → Add a machine** (Машины → Добавить машину). Панель генерирует код сопряжения (действителен 15 минут) и полную команду для вставки на целевой машине:

- **Windows** (PowerShell, любая версия):
  `& ([scriptblock]::Create((irm https://<panel>/install.ps1))) -PairCode MMOP-XXXX-XXXX`
- **Linux / macOS**:
  `curl -fsSL https://<panel>/install.sh | sh -s -- --pair-code MMOP-XXXX-XXXX`

Скрипт скачивает с панели архив под нужную платформу, проверяет его хеш SHA-256, устанавливает файлы, **сопрягает** агента (если код истёк, ошибка выводится сразу), затем регистрирует и запускает службу. Через несколько секунд машина появляется в панели со статусом `online`.

> Панель должна быть доступна с целевой машины (§3). Пока публичный URL не задан, команда использует адрес, по которому вы открыли панель.

### 2.2 Что делает скрипт — Windows

- Файлы в `%LOCALAPPDATA%\Programs\mmo-agent` (среда выполнения, `launcher.cjs`, `versions/<v>/agent.js`, `shawl.exe`), состояние в `%LOCALAPPDATA%\mmo-agent`.
- Служба `mmo-agent` регистрируется через **shawl** с автоматическим запуском; она работает **под вашей учётной записью Windows** (пароль запрашивается один раз, в открывающемся окне с повышенными правами), чтобы агент видел ваши подключённые сетевые диски и папки. Точнее: под учётной записью окна с повышенными правами — если UAC требует ввести данные другого администратора, служба будет работать именно под его учётной записью. Право "Log on as a service" (вход в качестве службы) предоставляется автоматически (если это не удаётся, скрипт продолжает работу и объясняет, как выдать его через `secpol.msc`). Альтернатива: `-ServiceAccount LocalSystem`.
- **Учётная запись без пароля** (вход по PIN-коду или вовсе без пароля): Windows запрещает службам вход с пустым паролем. Подтвердите пустой запрос пароля: скрипт сообщит об этом и зарегистрирует службу как `LocalSystem` (в этом случае агент не видит ваши подключённые сетевые диски). Чтобы вернуться к своей учётной записи: задайте пароль Windows и выполните команду ещё раз.
- Если в окне с повышенными правами что-то пошло не так, сообщение остаётся на экране (Enter — закрыть), а подробности пишутся в `%TEMP%\mmo-install.log`.
- Служба автоматически перезапускается при сбое; корректная остановка = Ctrl+C, переданный агенту, и **никогда** не всему дереву процессов: серверы Minecraft переживают остановку и обновление агента, после чего снова принимаются под управление.
- Опции: `-NoService` (только файлы), `-InstallDir`, `-StateDir`, `-Panel`, `-Archive <zip>` (офлайн).
- Удаление: `& ([scriptblock]::Create((irm https://<panel>/install.ps1))) -Uninstall` (добавьте `-Purge`, чтобы удалить и состояние; серверы Minecraft не затрагиваются никогда).

### 2.3 Что делает скрипт — Linux

- Файлы в `/opt/mmo-agent`, состояние в `/var/lib/mmo-agent`, при необходимости создаётся системная учётная запись `mmo` (`--user <name>` для другой учётной записи — агент должен иметь права на чтение/запись папок серверов).
- systemd-юнит `mmo-agent` с `KillMode=process` (отсоединённые серверы продолжают работать) и `Restart=on-failure`. `sudo` запрашивается при необходимости.
- **Без root**: `--user-service` устанавливает в `~/.local/share/mmo-agent` (файлы в `app/`, состояние в корне) с `systemctl --user` и `loginctl enable-linger` (запуск при загрузке без открытой сессии). Внимание: при запуске через `sudo` флаг `--user-service` игнорируется и выполняется общесистемная установка.
- Опции: `--no-service`, `--dir`, `--state-dir`, `--panel`, `--archive <tar.gz>` (офлайн).
- ⚠ **Права на ваши папки серверов.** Установленный как системная служба, агент работает от `mmo`, а не от вас: серверы, лежащие в `/home/<вы>/…`, для него часто доступны только на чтение. Панель предупреждает об этом сразу при усыновлении сервера («folder not writable»), а отклонённый запуск называет папку и учётную запись. Два способа, достаточно любого:
  - дать доступ учётной записи агента: `sudo chown -R mmo /путь/к/моим-серверам` (или `sudo chmod -R g+w` после `sudo usermod -aG <ваша-группа> mmo`);
  - либо установить агента от вашей учётной записи: `--user <вы>` (системная служба) или `--user-service` (без root).
- Удаление: `curl -fsSL https://<panel>/install.sh | sh -s -- --uninstall [--purge]` (добавьте `--user-service`, если устанавливали таким способом). Системная учётная запись `mmo` сохраняется (`userdel mmo`, если она больше не нужна).
- Под **WSL** виртуальная машина останавливается через несколько секунд после закрытия последнего терминала: вместе с ней останавливаются служба и серверы — WSL годится для экспериментов, но не для хостинга.

### 2.4 Что делает скрипт — macOS

Та же логика: `/opt/mmo-agent`, LaunchDaemon `com.mmo.agent` (`KeepAlive`, `AbandonProcessGroup`: серверы продолжают работать), учётная запись = пользователь, выполнивший `sudo`. `--user-service` создаёт вместо этого LaunchAgent (запуск только при входе в сессию). Журнал: `/var/lib/mmo-agent/agent.log`.

### 2.5 После перезагрузки машины

Служба перезапускает агента; агент снова принимает под управление ещё работающие серверы (PID + время запуска + командная строка) и, если включён параметр "Restore desired state when an agent boots" (восстанавливать желаемое состояние при запуске агента; Settings → General), запускает те, что были помечены `running`.

### 2.6 Офлайн-установка

Скачайте архив нужной платформы из панели (Settings → Agent distribution) или из релиза, скопируйте его вместе со скриптом (`install.ps1` / `install.sh` также лежат внутри архива) и выполните `install.ps1 -Archive <zip> -Panel https://<panel> -PairCode …` или `sh install.sh --archive <tar.gz> --panel https://<panel> --pair-code …` (хеш SHA-256 проверяется только для архива, скачанного с панели — локальный архив используется как есть).

## 3. Удалённый доступ (кратко)

Панель слушает только на `127.0.0.1`. Чтобы до неё могли добраться агенты на других машинах, ваши друзья и ваш телефон, выберите режим (Settings → Remote access):

| Режим                        | Кому подходит                                            | Что сделать                                                                                                                  |
| ---------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Tailscale** (по умолчанию) | Всем, включая тех, кто за CGNAT/4G                       | Установите Tailscale на хосте панели и на каждом клиентском устройстве, затем выполните показанную команду `tailscale serve` |
| **Direct**                   | У вас есть публичный IPv6 и домен (DuckDNS, Cloudflare…) | Укажите домен и DNS-провайдера, запросите сертификат (DNS-01), откройте порт 443 (IPv6-pinhole на роутере)                   |
| **Manual**                   | У вас уже есть свой reverse proxy                        | Направьте его на `127.0.0.1:3000` с поддержкой WebSocket                                                                     |

В любом случае карточка **Reachability test** (тест доступности; кнопка **Run the test** в Settings → Remote access) проверяет HTTP, WebSocket, бинарные кадры (64 КиБ) и сертификат TLS через публичный URL. Подробности и устранение неполадок: [FAQ по сети](network-faq.md). Добавление машин и адреса для игроков: [Добавление машины](add-a-machine.md).

## 4. На телефоне: установка PWA

Панель — это устанавливаемое веб-приложение (PWA): как только удалённый доступ настроен (§3 — для установки требуется HTTPS), откройте публичный URL в браузере телефона и добавьте приложение на главный экран:

- **Android (Chrome)**: меню ⋮ → "Add to Home screen" («Добавить на главный экран»; или "Install app" — «Установить приложение», если предлагается).
- **iOS (Safari)**: кнопка «Поделиться» → "Add to Home Screen". На iOS это **обязательное условие** для получения push-уведомлений: они работают только из установленного PWA, но не из Safari.

Приложение открывается на весь экран, с навигацией внизу экрана. Для уведомлений (сбой сервера, неудачная резервная копия, агент offline…): страница Account (учётная запись) → Push notifications — включите их, выберите категории и проверьте кнопкой "Send a test" (отправить тестовое уведомление). В режиме Tailscale на телефоне должно быть установлено приложение Tailscale, подключённое к вашему tailnet, — иначе панель недоступна.
