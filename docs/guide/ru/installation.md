# Установка

[English](../installation.md) · [Français](../fr/installation.md) · [Español](../es/installation.md) · [Deutsch](../de/installation.md) · [Português](../pt/installation.md) · **Русский** · [中文](../zh/installation.md)

_Перевод английской версии, которая является эталонной. Интерфейс приложения доступен на английском и французском языках._

Руководство пользователя — установите **панель** (одна машина, та, что остаётся включённой), затем **агент** на каждой машине, где размещены серверы Minecraft (часто это та же самая машина). Всё поставляется в виде самодостаточных архивов: заранее устанавливать Node, Java или Python не нужно.

Платформы с готовыми сборками: **Windows x64**, **Linux x64**, **Linux ARM64** (Raspberry Pi 4/5, ARM-серверы), **macOS Apple Silicon**. Windows ARM64 работает с архивом x64 (эмуляция). Intel macOS не пакетируется.

## 1. Панель

### 1.1 Скачивание

Скачайте архив `mmo-panel-<version>-<platform>.zip` (Windows) или `.tar.gz` (Linux / macOS) со страницы [релизов GitHub](https://github.com/Zlababababan/MinecraftManagerOnline/releases). Он содержит закреплённую среду выполнения Node, панель, веб-интерфейс и установочные архивы агента для всех 4 платформ (`dist-agent/`).

> Нет архива для вашей платформы? Соберите его из исходников в две команды: см. раздел «Быстрый старт» в [README](../../../README.ru.md).

### 1.2 Распаковка и запуск

**Windows** — распакуйте в постоянную папку, например `C:\mmo\panel`, затем:

```powershell
C:\mmo\panel\mmo-panel.cmd
```

**Linux / macOS**:

```bash
sudo mkdir -p /opt/mmo && sudo tar -xzf mmo-panel-*.tar.gz -C /opt/mmo
/opt/mmo/mmo-panel/mmo-panel.sh
```

Панель слушает на `http://127.0.0.1:3000` (никогда на всех интерфейсах — наружу её выводит слой доступа, §3; `0.0.0.0` отклоняется при запуске). Полезные переменные: `MMO_PORT`, `MMO_HOST` (конкретный адрес), `MMO_DATA_DIR` (по умолчанию `./data` рядом со скриптом — **именно эту папку нужно резервировать**: база данных SQLite, метрики, сертификаты, релизы). Помимо консоли, панель пишет свой журнал в `data/logs/panel-<date>.log` (хранится 14 дней) — именно туда стоит заглянуть, если что-то пошло не так после закрытия окна.

### 1.3 Первый запуск

Откройте `http://127.0.0.1:3000`: мастер настройки состоит из двух шагов — **Administrator account** (учётная запись администратора: имя пользователя, пароль, язык), затем **Access** (доступ): **публичный URL панели** (на этом этапе необязателен), **режим доступа** (см. §3) и **папка резервных копий по умолчанию**. Публичный URL можно изменить в любой момент в Settings → General: именно он подставляется в команды установки агентов и в push-уведомления — задайте его, как только удалённый доступ будет настроен.

### 1.4 Запуск при загрузке системы (служба)

**Windows** (shawl входит в архив) — в PowerShell **от имени администратора**:

```powershell
cd C:\mmo\panel
.\shawl.exe add --name mmo-panel --cwd C:\mmo\panel --log-dir C:\mmo\panel\logs --restart -- C:\mmo\panel\runtime\24.19.0\node.exe C:\mmo\panel\app\dist\main.js
sc.exe config mmo-panel start= delayed-auto
Start-Service mmo-panel
```

Служба при этом работает от имени `LocalSystem`; чтобы запустить её под вашей собственной учётной записью (рекомендуется, если резервные копии пишутся на сетевой диск), используйте `services.msc` → Log On (Вход в систему) либо адаптируйте процедуру для агента (§2.2). Переменные окружения (`MMO_PORT`…): `shawl add --env MMO_PORT=3000 …`.

> Важно: `mmo-panel.cmd` задаёт `MMO_WEB_DIR` и `MMO_DIST_DIR`; при использовании shawl добавьте их явно: `--env MMO_WEB_DIR=C:\mmo\panel\web --env MMO_DIST_DIR=C:\mmo\panel\dist-agent --env MMO_DATA_DIR=C:\mmo\panel\data`.

**Linux** (systemd) — `/etc/systemd/system/mmo-panel.service`:

```ini
[Unit]
Description=MinecraftManagerOnline panel
After=network-online.target
Wants=network-online.target

[Service]
User=mmo
WorkingDirectory=/opt/mmo/mmo-panel
ExecStart=/opt/mmo/mmo-panel/mmo-panel.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd --system --home-dir /opt/mmo/mmo-panel --shell /usr/sbin/nologin mmo
sudo chown -R mmo /opt/mmo/mmo-panel
sudo systemctl daemon-reload && sudo systemctl enable --now mmo-panel
```

**macOS** (launchd) — `/Library/LaunchDaemons/com.mmo.panel.plist` с `ProgramArguments` = `/opt/mmo/mmo-panel/mmo-panel.sh`, `RunAtLoad` и `KeepAlive` установлены в `true`, затем `sudo launchctl bootstrap system /Library/LaunchDaemons/com.mmo.panel.plist`.

### 1.5 Обновление панели

Остановите службу, распакуйте новый архив **поверх** старого (папка `data/` никогда не входит в архив), перезапустите. Миграции базы данных выполняются при запуске. Новый архив содержит агентов той же версии: панель автоматически публикует релиз агента, и если включён флажок "Update agents automatically when they connect" (обновлять агентов автоматически при подключении; Settings → General — по умолчанию выключен), каждый агент обновляется при своём следующем подключении, с автоматическим откатом при сбое. В противном случае обновляйте их по одному из карточки Agent на странице каждой машины.

### 1.6 Резервное копирование и восстановление панели

Панель раз в сутки сама создаёт свою резервную копию (согласованная копия базы данных через `VACUUM INTO`) в `data/backups/panel/mmo-<date>.db`, хранится 7 копий; в Settings → Panel backups можно создать копию по требованию. Метрики (`metrics.db`) не копируются: их можно восстановить, а места они занимают много. Резервируйте также всю папку `data/`, если хотите сохранить сертификаты и архивы агентов.

Чтобы **восстановить**: остановите панель (службу или Ctrl+C), затем:

```powershell
C:\mmo\panel\mmo-panel.cmd restore mmo-2026-08-23T01-00-00.db
```

```bash
/opt/mmo/mmo-panel/mmo-panel.sh restore mmo-2026-08-23T01-00-00.db
```

Для копии, лежащей в `data/backups/panel/`, достаточно одного имени файла; полный путь тоже принимается. Копия проверяется (`integrity_check`), текущая база данных сохраняется как `mmo.db.before-restore-<date>`, после чего панель можно перезапустить: агенты переподключаются со своим прежним секретом, а размещённые на них серверы снова принимаются под управление с теми же идентификаторами (файл-маркер `.mmo-server.json`). Всё, что было создано после резервной копии (пользователи, сопряжённые машины, настройки), теряется: машину, сопряжённую после создания копии, придётся сопрягать заново. Восстановление отказывается запускаться, если `mmo.db-wal` не пуст (панель ещё работает или была завершена аварийно — запустите её, корректно остановите и повторите попытку).

## 2. Агенты

Один агент на каждую машину с серверами. Он подключается к панели **исходящим** соединением (WebSocket): на машинах с агентами не нужно открывать ни одного порта.

### 2.1 Команда в одну строку

В панели: **Machines → Add a machine** (Машины → Добавить машину). Панель генерирует код сопряжения (действителен 15 минут) и полную команду для вставки на целевой машине:

- **Windows** (PowerShell, любая версия):
  `& ([scriptblock]::Create((irm https://<panel>/install.ps1))) -PairCode MMOP-XXXX-XXXX`
- **Linux / macOS**:
  `curl -fsSL https://<panel>/install.sh | sh -s -- --pair-code MMOP-XXXX-XXXX`

Скрипт скачивает с панели архив под нужную платформу, проверяет его хеш SHA-256, устанавливает файлы, **сопрягает** агента (если код истёк, ошибка выводится сразу), затем регистрирует и запускает службу. Через несколько секунд машина появляется в панели со статусом `online`.

> Панель должна быть доступна с целевой машины (§3). Пока публичный URL не задан, команда использует адрес, по которому вы открыли панель.

### 2.2 Что делает скрипт — Windows

- Файлы в `%LOCALAPPDATA%\Programs\mmo-agent` (среда выполнения, `launcher.cjs`, `versions/<v>/agent.js`, `shawl.exe`), состояние в `%LOCALAPPDATA%\mmo-agent`.
- Служба `mmo-agent` регистрируется через **shawl** с автоматическим запуском; она работает **под вашей учётной записью Windows** (пароль запрашивается один раз, в открывающемся окне с повышенными правами), чтобы агент видел ваши подключённые сетевые диски и папки. Точнее: под учётной записью окна с повышенными правами — если UAC требует ввести данные другого администратора, служба будет работать именно под его учётной записью. Право "Log on as a service" (вход в качестве службы) предоставляется автоматически (если это не удаётся, скрипт продолжает работу и объясняет, как выдать его через `secpol.msc`). Альтернатива: `-ServiceAccount LocalSystem`.
- **Учётная запись без пароля** (вход по PIN-коду или вовсе без пароля): Windows запрещает службам вход с пустым паролем. Подтвердите пустой запрос пароля: скрипт сообщит об этом и зарегистрирует службу как `LocalSystem` (в этом случае агент не видит ваши подключённые сетевые диски). Чтобы вернуться к своей учётной записи: задайте пароль Windows и выполните команду ещё раз.
- Если в окне с повышенными правами что-то пошло не так, сообщение остаётся на экране (Enter — закрыть), а подробности пишутся в `%TEMP%\mmo-install.log`.
- Служба автоматически перезапускается при сбое; корректная остановка = Ctrl+C, переданный агенту, и **никогда** не всему дереву процессов: серверы Minecraft переживают остановку и обновление агента, после чего снова принимаются под управление.
- Опции: `-NoService` (только файлы), `-InstallDir`, `-StateDir`, `-Panel`, `-Archive <zip>` (офлайн).
- Удаление: `& ([scriptblock]::Create((irm https://<panel>/install.ps1))) -Uninstall` (добавьте `-Purge`, чтобы удалить и состояние; серверы Minecraft не затрагиваются никогда).

### 2.3 Что делает скрипт — Linux

- Файлы в `/opt/mmo-agent`, состояние в `/var/lib/mmo-agent`, при необходимости создаётся системная учётная запись `mmo` (`--user <name>` для другой учётной записи — агент должен иметь права на чтение/запись папок серверов).
- systemd-юнит `mmo-agent` с `KillMode=process` (отсоединённые серверы продолжают работать) и `Restart=on-failure`. `sudo` запрашивается при необходимости.
- **Без root**: `--user-service` устанавливает в `~/.local/share/mmo-agent` (файлы в `app/`, состояние в корне) с `systemctl --user` и `loginctl enable-linger` (запуск при загрузке без открытой сессии). Внимание: при запуске через `sudo` флаг `--user-service` игнорируется и выполняется общесистемная установка.
- Опции: `--no-service`, `--dir`, `--state-dir`, `--panel`, `--archive <tar.gz>` (офлайн).
- Удаление: `curl -fsSL https://<panel>/install.sh | sh -s -- --uninstall [--purge]` (добавьте `--user-service`, если устанавливали таким способом). Системная учётная запись `mmo` сохраняется (`userdel mmo`, если она больше не нужна).
- Под **WSL** виртуальная машина останавливается через несколько секунд после закрытия последнего терминала: вместе с ней останавливаются служба и серверы — WSL годится для экспериментов, но не для хостинга.

### 2.4 Что делает скрипт — macOS

Та же логика: `/opt/mmo-agent`, LaunchDaemon `com.mmo.agent` (`KeepAlive`, `AbandonProcessGroup`: серверы продолжают работать), учётная запись = пользователь, выполнивший `sudo`. `--user-service` создаёт вместо этого LaunchAgent (запуск только при входе в сессию). Журнал: `/var/lib/mmo-agent/agent.log`.

### 2.5 После перезагрузки машины

Служба перезапускает агента; агент снова принимает под управление ещё работающие серверы (PID + время запуска + командная строка) и, если включён параметр "Restore desired state when an agent boots" (восстанавливать желаемое состояние при запуске агента; Settings → General), запускает те, что были помечены `running`.

### 2.6 Офлайн-установка

Скачайте архив нужной платформы из панели (Settings → Agent distribution) или из релиза, скопируйте его вместе со скриптом (`install.ps1` / `install.sh` также лежат внутри архива) и выполните `install.ps1 -Archive <zip> -Panel https://<panel> -PairCode …` или `sh install.sh --archive <tar.gz> --panel https://<panel> --pair-code …` (хеш SHA-256 проверяется только для архива, скачанного с панели — локальный архив используется как есть).

## 3. Удалённый доступ (кратко)

Панель слушает только на `127.0.0.1`. Чтобы до неё могли добраться агенты на других машинах, ваши друзья и ваш телефон, выберите режим (Settings → Remote access):

| Режим                        | Кому подходит                                            | Что сделать                                                                                                                  |
| ---------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Tailscale** (по умолчанию) | Всем, включая тех, кто за CGNAT/4G                       | Установите Tailscale на хосте панели и на каждом клиентском устройстве, затем выполните показанную команду `tailscale serve` |
| **Direct**                   | У вас есть публичный IPv6 и домен (DuckDNS, Cloudflare…) | Укажите домен и DNS-провайдера, запросите сертификат (DNS-01), откройте порт 443 (IPv6-pinhole на роутере)                   |
| **Manual**                   | У вас уже есть свой reverse proxy                        | Направьте его на `127.0.0.1:3000` с поддержкой WebSocket                                                                     |

В любом случае карточка **Reachability test** (тест доступности; кнопка **Run the test** в Settings → Remote access) проверяет HTTP, WebSocket, бинарные кадры (64 КиБ) и сертификат TLS через публичный URL. Подробности и устранение неполадок: [FAQ по сети](network-faq.md). Добавление машин и адреса для игроков: [Добавление машины](add-a-machine.md).

## 4. На телефоне: установка PWA

Панель — это устанавливаемое веб-приложение (PWA): как только удалённый доступ настроен (§3 — для установки требуется HTTPS), откройте публичный URL в браузере телефона и добавьте приложение на главный экран:

- **Android (Chrome)**: меню ⋮ → "Add to Home screen" («Добавить на главный экран»; или "Install app" — «Установить приложение», если предлагается).
- **iOS (Safari)**: кнопка «Поделиться» → "Add to Home Screen". На iOS это **обязательное условие** для получения push-уведомлений: они работают только из установленного PWA, но не из Safari.

Приложение открывается на весь экран, с навигацией внизу экрана. Для уведомлений (сбой сервера, неудачная резервная копия, агент offline…): страница Account (учётная запись) → Push notifications — включите их, выберите категории и проверьте кнопкой "Send a test" (отправить тестовое уведомление). В режиме Tailscale на телефоне должно быть установлено приложение Tailscale, подключённое к вашему tailnet, — иначе панель недоступна.
