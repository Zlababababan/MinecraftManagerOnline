Панель слушает **только** на `127.0.0.1` (или на конкретном адресе через `MMO_HOST`). Есть три способа добраться до неё извне; достаточно одного.

## Tailscale (по умолчанию, рекомендуется)

**Почему**: работает за CGNAT, через 4G и гостиничный Wi-Fi, без открытия портов; автоматический сертификат HTTPS; бесплатный тариф до 6 пользователей (на некоторых предложениях 3 — проверьте).

1. Установите [Tailscale](https://tailscale.com/download) на хосте панели, войдите в учётную запись.
2. В панели, Settings → Remote access (настройки → удалённый доступ), режим **Tailscale**: скопируйте и выполните показанную команду вида
   `tailscale serve --bg --https=443 http://127.0.0.1:3000`.
   Включите **MagicDNS** и **HTTPS certificates** в консоли Tailscale, если это ещё не сделано.
3. Публичным URL становится `https://<machine>.<tailnet>.ts.net`: укажите его в Settings → General.
4. На каждом клиентском устройстве (телефон, ПК друга, удалённая машина с агентом): установите Tailscale и подключитесь к **тому же tailnet** (пригласите друзей или предоставьте общий доступ к узлу).
5. Запустите **Reachability test** (тест доступности; тот же экран, кнопка **Run the test**): HTTP, WebSocket, бинарные кадры и сертификат TLS (бинарные кадры проходят через `tailscale serve`).

Агенты: команда установки использует URL `https://…ts.net`; значит, на машине агента тоже нужен Tailscale. Серверы Minecraft: публикация **Tailnet**, адрес `100.x.y.z:25565`.

Устранение неполадок: `tailscale status` на хосте; `tailscale serve status` должен показывать прокси (`No serve config` = команда serve ни разу не выполнялась — тест доступности в этом случае завершается отказом в соединении на порту 443); если тест WebSocket не проходит, а HTTP проходит, проверьте, нет ли перед панелью ещё одного прокси (nginx) без `Upgrade`. Если терминал отвечает, что команда `tailscale` не распознана (Windows), CLI отсутствует в PATH: вызовите его по полному пути в **двойных** кавычках (одинарные в Windows ломаются) — Command Prompt: `"C:\Program Files\Tailscale\tailscale.exe" serve …`, PowerShell: то же самое с `&` в начале (подставьте свою папку установки).

## Direct (IPv6 + собственный домен)

**Почему**: без посредников, друзьям ничего устанавливать не нужно. **Требование**: публичный IPv6 (есть у большинства домашних роутеров) — IPv4 за CGNAT недостаточно.

1. Домен: бесплатно через **DuckDNS** (`your-name.duckdns.org`) или домен на Cloudflare; либо любой провайдер в режиме **manual** (записи вы создаёте сами).
2. Settings → Remote access, режим **Direct**: домен, DNS-провайдер, токен (DuckDNS: токен с сайта; Cloudflare: API-токен с правом `Zone:DNS:Edit`), e-mail для ACME. **Save** (сохранить), затем **Request a certificate** (запросить сертификат): панель создаёт TXT-запись `_acme-challenge` (или показывает её вам в режиме manual), ждёт распространения DNS, получает сертификат Let's Encrypt и открывает HTTPS-прослушиватель на вашем глобальном IPv6-адресе, порт 443.
3. **Динамический DNS**: переключатель "Update the AAAA record automatically" (обновлять AAAA-запись автоматически) — панель обновляет AAAA-запись каждые 10 минут (DuckDNS/Cloudflare/произвольный URL). В режиме manual направьте AAAA-запись на показанный IPv6-адрес самостоятельно.
4. **Роутер / брандмауэр**: на роутере создайте IPv6-_pinhole_ (Freebox: «Ouvrir un port IPv6»; Livebox: «Pare-feu IPv6») на адрес хоста, порт 443 TCP. На хосте добавьте правило, показанное в Settings → Remote access → **Firewall rules** (правила брандмауэра; PowerShell `New-NetFirewallRule` / `ufw allow`). _Временные_ IPv6-адреса (privacy extensions) со временем меняются: панель выбирает стабильный адрес, замеченный на предыдущем тике; при сомнениях зафиксируйте адрес в поле "Public IPv6 address".
5. Публичный URL: `https://your-name.duckdns.org` (Settings → General), затем запустите **Reachability test**.

Серверы Minecraft: публикация **Direct**, pinhole + правило брандмауэра на каждый игровой порт (показывается там же). Игроки, у которых есть только IPv4, подключиться не смогут: для них предпочтительнее Tailscale.

Продление сертификата: автоматическое, проверяется ежедневно, как только остаётся < 30 дней — кроме режима DNS manual (панель предупредит: запросите сертификат заново).

## Manual (существующий reverse proxy)

Направьте свой прокси (Caddy, nginx, Traefik…) на `http://127.0.0.1:3000` **с поддержкой WebSocket** (`Upgrade`/`Connection`) и кадрами не менее 16 МБ и пробрасывайте заголовки `X-Forwarded-Proto` / `X-Forwarded-Host`. Пример для Caddy:

```
panel.example.org {
    reverse_proxy 127.0.0.1:3000
}
```

Укажите публичный URL и запустите тест доступности: строка "Seen via" в результате показывает "a reverse-proxy", когда заголовки пробрасываются корректно.

## Часто задаваемые вопросы

**Агент остаётся `offline` после установки.** Проверьте журналы на машине — Windows: `launcher.log` в корне `%LOCALAPPDATA%\Programs\mmo-agent` и журналы службы в её подпапке `logs\`; Linux: `journalctl -u mmo-agent -f` (`--user`, если устанавливали с `--user-service`); macOS: `/var/lib/mmo-agent/agent.log`. Обычные причины: URL панели недоступен с этой машины (Tailscale не установлен или не подключён, брандмауэр), сертификат не является доверенным (режим manual с частным CA: добавьте его в системное хранилище), истёкший код сопряжения (сообщение `pairing failed` выводится во время установки) или состояние агента, унаследованное от другой панели (`unknown, unpaired or disabled agent` в журналах — установщик автоматически выполняет повторное сопряжение; в крайнем случае удалите агента с `-Purge` / `--purge` и выполните команду установки заново).

**Панель доступна, но WebSocket не работает.** Прокси без `Upgrade` или со слишком коротким тайм-аутом простоя. Тест доступности показывает, какой именно шаг не проходит (HTTP, WebSocket, Binary frames, TLS certificate).

**Push-уведомления не приходят.** Им требуется HTTPS (Tailscale или Direct), а на iOS — установка PWA на главный экран (страница Account → Push notifications проведёт вас по шагам; см. также [Установка § 4](installation.md#4-на-телефоне-установка-pwa)). Кнопка "Send a test" там же проверяет всю цепочку.

**Сервер выключается при остановке или обновлении агента.** Так быть не должно: серверы отсоединены (detached), а служба настроена завершать только агента (`KillMode=process`, `AbandonProcessGroup`, shawl). Если вы устанавливали службу вручную, проверьте этот параметр; никогда не применяйте `taskkill /T` к агенту.

**Только IPv4 (нет IPv6 на роутере).** Режим Direct невозможен без публичного проброса IPv4-порта; используйте Tailscale.

**Порты.** Панель: 443 входящий (только режим Direct). Агенты: входящих портов нет. Серверы Minecraft: 25565/TCP (и любые выбранные вами порты) в режиме Direct.

## Межсетевой экран

По умолчанию панель не открывает наружу **ничего**: она слушает только `127.0.0.1`. Поэтому в режиме **Tailscale** нигде не нужно открывать ни одного правила — tailnet добирается до панели исходящим соединением. В режиме **Direct** откройте на хосте входящий HTTPS-порт, который вы выбрали (по умолчанию 443) — точная команда показана в Settings → Remote access → **Firewall rules** (правила межсетевого экрана).

**Oracle Cloud** (бесплатная ВМ часто становится домом для панели): здесь два отдельных барьера, и открыть нужно оба.

- На самой ВМ правила iptables образа Ubuntu от Oracle заканчиваются глобальным REJECT: открывающее правило нужно **вставить перед ним**. `-I` (insert) делает именно это; `-A` (append) окажется после REJECT и ничего не даст.

  ```bash
  sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
  sudo netfilter-persistent save
  ```

- **Security List** сети VCN настраивается в веб-консоли Oracle, а не на ВМ: добавьте и там входящее правило для TCP 443 (Networking → Virtual cloud networks → ваша VCN → Security Lists).

С Tailscale ничего этого не требуется — ни iptables, ни Security List: во многом ради этого режим по умолчанию и выбран.

## Своя воля для каждой машины

Режим — это значение по умолчанию, а не стена. Машина, которая не может войти в tailnet (арендованная ВМ, сервер друга), может подключиться по **прямому** адресу, пока остальные продолжают пользоваться Tailscale: в Settings → Remote access включите **«Also answer on the direct route»** (отвечать также по прямому пути) и настройте ниже домен и сертификат — панель начнёт отвечать по обоим путям сразу.

Каждый агент помнит адрес, с которым он был привязан. Когда вы создаёте код привязки со страницы машины, появляется (как только есть из чего выбирать) селектор **«Panel address for this machine»** (адрес панели для этой машины): выберите URL по умолчанию или прямой путь, и команда установки будет пересобрана с этим адресом. На уже привязанных машинах менять ничего не нужно — они сохраняют свой путь.
